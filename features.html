01 • Executive Summary

What ScoreX is

ScoreX is an Android cricket scoring application built to manage a match from initial setup through live delivery entry, innings management, statistics, scorecard review, graphs, local match history and PDF scorecard generation.

The central design idea is delivery-level state. A single delivery can affect the team score, batsman runs, balls, bowler statistics, legal-ball count, strike, partnership and wicket state. ScoreX keeps these related changes coordinated through its scoring/model layer rather than treating the score as a single text value.

02 • Problem, Objectives & Scope

Why ScoreX exists

Problem Statement

Manual cricket scoring requires continuous calculations and synchronized tracking. When a wide, no-ball, wicket, partnership change or run-out occurs, several statistics may need to change at the same time. ScoreX addresses this by recording delivery events and maintaining structured information for players, bowlers, overs, partnerships and innings.

Objectives

  • Easy-to-use Android interface
  • Reduce repetitive manual calculations
  • Consistent batting, bowling and partnership data
  • Structured scorecard
  • Visual scoring graphs
  • Local match history
  • Shareable PDF scorecards

Current Scope

The current scope covers local match scoring and review: match setup, live scoring, special deliveries, wickets, innings transitions, result calculation, scorecard, graphs, history, settings and PDF export. It does not claim cloud synchronization, online accounts or a remote database.

Core objects: Match, Ball, Player, Bowler, Over, Partnership, MatchManager and SavedMatch.

Live scoring follows: create and configure the match → select opening players → record deliveries → update player, bowler, partnership and over information → process special deliveries and wickets → use Undo if needed → complete innings → calculate result → review Scorecard, Graphs, History and PDF.

06 • Cricket Scoring Rules

Special deliveries and wickets

Wide

Wide is an extra. The project contains configurable wide behavior, including configured run value and re-ball/legal-ball behavior.

No Ball

No Ball records the no-ball extra separately from batsman runs and follows the project's legal-ball/re-ball behavior.

Bye / Leg Bye

These add to team extras without becoming batsman runs.

Run Out

Completed runs are retained when the wicket is recorded.

W1 + W2 + W4 + W

Undo

Undo reverses the latest delivery and related scoring state.

Innings

First and second innings are maintained separately so the chase and final result can be evaluated.

08 • Storage & Privacy

Local-first by design

Storage

  • Match History — Java serialization (.ser)
  • Settings — SharedPreferences
  • PDF exports — local scorex_exports files

Current Constraints

  • No remote database or account system
  • No built-in multi-device collaboration
  • Local storage limits retained history/PDFs
  • No cloud synchronization
